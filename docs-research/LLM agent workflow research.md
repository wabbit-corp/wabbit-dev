LLM-Powered Agents and Workflows for Code Documentation and Analysis
====================================================================

Introduction
------------

Recent advances in large language models (LLMs) have led to new tools and research for automating various software engineering tasks. In particular, LLM-powered systems are being developed to assist with code **documentation**, **code analysis** (including static analysis and code review), **README generation**, **usage example creation**, and even **semantic linting**. These solutions range from single-step (non-agentic) applications where an LLM directly produces an output from a prompt, to multi-step **agentic** workflows that use multiple tools or iterative reasoning. Below, we survey notable research papers, open-source projects, and industry implementations in these areas, highlighting each system’s goals and methods. A summary table is provided at the end for quick reference.

LLMs for Code Documentation Generation
--------------------------------------

High-quality code documentation (docstrings, API comments, etc.) is essential yet labor-intensive to write. Several LLM-based approaches aim to generate documentation automatically:

*   **DocAgent (ACL 2025)** – _Multi-agent docstring generator._ DocAgent is a novel framework that uses multiple specialized agents (Reader, Searcher, Writer, Verifier, Orchestrator) to collaboratively produce code documentation[aclanthology.org](https://aclanthology.org/2025.acl-demo.44.pdf#:~:text=factually%20incor%02rect%20outputs,Our%20ablation%20study%20confirms%20the)[aclanthology.org](https://aclanthology.org/2025.acl-demo.44.pdf#:~:text=building,a%20robust%20approach%20for%20reliable). It processes the codebase in a topologically sorted dependency order, building context incrementally to avoid missing important details[aclanthology.org](https://aclanthology.org/2025.acl-demo.44.pdf#:~:text=To%20tackle%20these%20challenges%2C%20we,This%20mimics%20human%20workflows). This agentic workflow mimics how a human would navigate complex code, and it includes a verification step to reduce hallucinations. In experiments, DocAgent achieved superior completeness and accuracy of docstrings compared to baseline LLM approaches[aclanthology.org](https://aclanthology.org/2025.acl-demo.44.pdf#:~:text=factually%20incor%02rect%20outputs,Our%20ablation%20study%20confirms%20the). The authors provide a demo and open-source code for DocAgent[aclanthology.org](https://aclanthology.org/2025.acl-demo.44.pdf#:~:text=multi,a%20robust%20approach%20for%20reliable)[aclanthology.org](https://aclanthology.org/2025.acl-demo.44.pdf#:~:text=1%20https%3A%2F%2Fgithub,Appendix%20C%20for%20more%20details).
*   **Comparative LLM Evaluation for Documentation (Dvivedi et al., 2024)** – _Benchmarking LLMs on code docs._ This study compares GPT-3.5, GPT-4, Google Bard, LLaMA-2, and StarChat on generating function-level and file-level documentation[arxiv.org](https://arxiv.org/abs/2312.10349#:~:text=,4%2C%20and%20Bard%20exhibit). Using a checklist-based evaluation for accuracy, completeness, and clarity, they found that LLM-generated docs often outperform original human-written docs in quality[arxiv.org](https://arxiv.org/abs/2312.10349#:~:text=Accuracy%2C%20Completeness%2C%20Relevance%2C%20Understandability%2C%20Readability,Considering%20the%20time%20taken%20for). Proprietary models (GPT-4, etc.) scored higher than open-source models, and function-level docstrings were markedly better than whole-file summaries[arxiv.org](https://arxiv.org/abs/2312.10349#:~:text=based%20system%20to%20minimize%20subjectivity%2C,worse%20performance%20across%20all%20parameters)[arxiv.org](https://arxiv.org/abs/2312.10349#:~:text=documentation.%20Notably%2C%20closed,inline%20and%20function%20level%20documentation). This suggests current LLMs are quite effective at filling in missing comments, though file-level or module-level documentation remains challenging.
*   **Context-Aware Javadoc Generation (Sarker & Ifty, 2025)** – _LLM with structured context for Java._ Sarker et al. address automated Javadoc creation by assembling a specialized dataset that provides each Java method’s code **plus** rich context (e.g. class hierarchy, semantic info)[arxiv.org](https://arxiv.org/html/2509.14273v1#:~:text=developing%20a%20tailored%20dataset%20and,offering%20a%20viable%20alternative%20to). They fine-tuned and evaluated several open-source LLMs (e.g. LLaMA 3.1, Mistral) under zero-shot, few-shot, and fine-tuned settings[arxiv.org](https://arxiv.org/html/2509.14273v1#:~:text=work%2C%20we%20present%20a%20novel%2C,viable%20alternative%20to%20proprietary%20systems). Results showed that an advanced LLaMA model produced consistently high-quality Javadocs, approaching the quality of proprietary models[arxiv.org](https://arxiv.org/html/2509.14273v1#:~:text=codebases.%20We%20evaluate%20five%20open,viable%20alternative%20to%20proprietary%20systems). This work demonstrates that with proper training data (including structural code context), LLMs can generate template-based docs (like Javadoc) reliably. The code and dataset were made available for others[arxiv.org](https://arxiv.org/html/2509.14273v1#:~:text=1%20Introduction).
*   **AutoDoc-ChatGPT (Open Source Tool, 2023)** – _One-shot documentation script._ AutoDoc-ChatGPT is a community-developed Python CLI that connects to OpenAI’s ChatGPT API to generate documentation for a given codebase automatically[github.com](https://github.com/topics/automated-documentation#:~:text=AutoDoc,comprehensive%20documentation%20for%20your%20codebase). It traverses source files and uses prompts to produce docstrings or markdown docs. This non-agentic tool illustrates a straightforward use of LLMs: given code input, output a doc in one pass. While simple, it shows decent results for adding comments in any programming language and has been adopted by developers to quickly improve code comments.
*   **AgentHub Documentation Bot (Brodeur-Urbas, 2023)** – _Pipeline that writes docs and commits to Git._ An engineer built an automated doc bot using AgentHub (a framework for LLM pipelines) to keep his project documentation up-to-date[medium.com](https://medium.com/better-programming/automating-open-source-documentation-with-gpt4-5b6405881b1b#:~:text=I%20built%20an%20LLM,My%20sand%20castle%20rebuilds%20itself). The bot reads all files in the GitHub repo, then for each file it invokes GPT-4 with a prompt to **“generate markdown documentation for this code”**, structured into sections like Summary, Inputs, Parameters, Outputs, etc.[medium.com](https://medium.com/better-programming/automating-open-source-documentation-with-gpt4-5b6405881b1b#:~:text=Ask%20ChatGPT%3A). It then commits the generated `.md` files back to the repository in a pull request. This agentic workflow effectively treats documentation as a continuously regenerable artifact: whenever code changes, the pipeline can be re-run to refresh the docs. The approach trades off some human nuance in writing style for consistency and currency of documentation.
*   **MCP (Model-Context Protocol) Documentation System (Sharma, 2023)** – _Integrated RAG-based doc generation._ An industry blog post outlines an experimental “MCP-powered” documentation workflow that combines LLMs with retrieval and tool use[ai.codersarts.com](https://www.ai.codersarts.com/post/mcp-powered-code-documentation-generator-intelligent-documentation-creation-with-rag-integration#:~:text=MCP,Augmented%20Generation%29%20integration)[ai.codersarts.com](https://www.ai.codersarts.com/post/mcp-powered-code-documentation-generator-intelligent-documentation-creation-with-rag-integration#:~:text=Automated%20API%20Documentation%20Generation). Here, an AI agent uses standardized interfaces (the MCP protocol) to pull in live information: it can inspect code repositories, query documentation databases, and apply coding best practices from external knowledge. The LLM then generates comprehensive docs including function descriptions, parameter definitions, **usage examples**, integration guides, etc., all tailored to the project’s style[ai.codersarts.com](https://www.ai.codersarts.com/post/mcp-powered-code-documentation-generator-intelligent-documentation-creation-with-rag-integration#:~:text=Automated%20API%20Documentation%20Generation)[ai.codersarts.com](https://www.ai.codersarts.com/post/mcp-powered-code-documentation-generator-intelligent-documentation-creation-with-rag-integration#:~:text=Open%20source%20maintainers%20leverage%20MCP,maintaining%20technical%20completeness%20and%20accuracy). This resembles a highly agentic approach where the LLM plans and calls tools to gather context. By leveraging retrieval augmentation, the system aims to reduce hallucinations and keep documentation accurate. While largely conceptual, it showcases how enterprise documentation needs (legacy code explanations, architecture overviews, etc.) might be automated with a network of LLM-driven helpers.

LLMs for Code Analysis and Static Analysis
------------------------------------------

Beyond documentation, LLMs are being applied to understand and improve code quality. This includes analyzing code for bugs, security issues, or stylistic problems – tasks traditionally done by static analysis tools or human reviewers.

*   **LLM-Assisted Static Analysis (Li et al., ESEC/FSE 2023)** – _Using ChatGPT to reduce false alarms._ Researchers from UC Riverside explored using ChatGPT to generate precise function summaries that help a static analyzer be more accurate[zhyfeng.github.io](https://zhyfeng.github.io/files/2023-FSE-IVR.pdf#:~:text=This%20paper%20explores%20the%20possibility,false%20positives%20and%20false%20negatives)[zhyfeng.github.io](https://zhyfeng.github.io/files/2023-FSE-IVR.pdf#:~:text=We%20develop%20a%20systematic%20methodology,effectively%20eliminating%20false%20positive%20cases). Static analysis often flags many false positives (non-bugs) due to limited reasoning about program semantics. By prompting ChatGPT (and GPT-4) with the function’s code, they obtained high-level summaries of what the code does, especially for tricky constructs like loops or pointer logic[zhyfeng.github.io](https://zhyfeng.github.io/files/2023-FSE-IVR.pdf#:~:text=Models%20,false%20positives%20and%20false%20negatives). These LLM-generated summaries, when fed into a static analysis tool (UBITect), eliminated many false positives and even caught a few missed true bugs[zhyfeng.github.io](https://zhyfeng.github.io/files/2023-FSE-IVR.pdf#:~:text=We%20develop%20a%20systematic%20methodology,both%20false%20positives%20and%20false). In a pilot study, their method provided exact correct summaries for 16 of 20 challenging functions, effectively resolving those static analysis warnings[zhyfeng.github.io](https://zhyfeng.github.io/files/2023-FSE-IVR.pdf#:~:text=has%20been%20evaluated%20on%20false,false%20negatives%20in%20static%20analysis). The team released their implementation (“GPT-Expr”) as open source[zhyfeng.github.io](https://zhyfeng.github.io/files/2023-FSE-IVR.pdf#:~:text=%E2%80%A2%20We%20evaluate%20our%20approach,Expr) – a practical example of a non-agent LLM augmenting an existing analyzer.
*   **LLMs as Code Analysts (Fang et al., USENIX Security 2024)** – _Evaluating LLMs on code understanding and vuln detection._ Fang and colleagues conducted one of the first systematic studies of LLMs for code analysis tasks[usenix.org](https://www.usenix.org/system/files/usenixsecurity24-fang.pdf#:~:text=LLMs%E2%80%99%20capabilities%20in%20performing%20code,applications%20in%20this%20critical%20domain). They built a dataset of real-world code (including intentionally **obfuscated** code) and tested whether models like ChatGPT could correctly interpret and detect issues in the code[usenix.org](https://www.usenix.org/system/files/usenixsecurity24-fang.pdf#:~:text=Amidst%20all%20possibilities%20of%20LLMs%2C,malicious%20parties%20have%20lever%02aged%20code)[usenix.org](https://www.usenix.org/system/files/usenixsecurity24-fang.pdf#:~:text=and%20avoid%20being%20detected,analytical%20studies%20on%20this%20topic). Their findings indicate LLMs can serve as valuable automated code analysts – for example, describing what a piece of malware does – but with notable limitations[usenix.org](https://www.usenix.org/system/files/usenixsecurity24-fang.pdf#:~:text=LLMs%E2%80%99%20capabilities%20in%20performing%20code,applications%20in%20this%20critical%20domain). In case studies on analyzing malicious software, the LLM could often identify suspicious patterns, but struggled with heavily obfuscated logic and occasionally produced incorrect conclusions[usenix.org](https://www.usenix.org/system/files/usenixsecurity24-fang.pdf#:~:text=3,first%20paper%20that%20pro%02vides%20a)[usenix.org](https://www.usenix.org/system/files/usenixsecurity24-fang.pdf#:~:text=5%20Case%20Studies%20In%20this,one). The paper highlights that while LLMs do not “understand” code in a formal sense, they can recognize patterns and offer insights that complement traditional static analysis, especially when code is complex. However, caution is needed due to possible errors, and the authors advocate for a human-in-the-loop or verification layer for critical use cases[tomarcher.io](https://tomarcher.io/posts/how-large-languag-models-read-code/#:~:text=In%20safety,the%20formal%20rigor%20of%20compilers)[tomarcher.io](https://tomarcher.io/posts/how-large-languag-models-read-code/#:~:text=The%20real%20frontier%20lies%20in,anomalies%2C%20and%20predicting%20downstream%20effects).
*   **Datadog’s “Bits AI” for Static Code Analysis (2024)** – _Filtering static analyzer alerts with an LLM._ Cloud company Datadog embedded an LLM-powered assistant (codenamed “Bits AI”) into their static application security testing (SAST) pipeline to automatically triage findings[datadoghq.com](https://www.datadoghq.com/blog/using-llms-to-filter-out-false-positives/#:~:text=Datadog%E2%80%99s%20new%20false%20positive%20filtering,the%20vulnerabilities%20that%20matter%20most). When the static analyzer flags a potential vulnerability, Bits AI inspects the surrounding code and assesses whether the issue is a **true positive or a false positive**[datadoghq.com](https://www.datadoghq.com/blog/using-llms-to-filter-out-false-positives/#:~:text=adding%20AI,to%20relevant%20findings). It provides a brief explanation of its reasoning next to each alert. This helps developers focus on the real problems instead of wading through noise. The key idea is that an LLM can reason about code context in ways static rules cannot: e.g. understanding data flow, validation logic, and whether a seemingly dangerous call is actually safe in context[datadoghq.com](https://www.datadoghq.com/blog/using-llms-to-filter-out-false-positives/#:~:text=An%20LLM%20introduces%20the%20ability,for%20exploitation%20are%20actually%20met). In essence, this is semantic reasoning or _semantic linting_ – the LLM may conclude that a suspected SQL injection is not exploitable because the input is sanitized, and label it as a likely false positive. Datadog reports that this integration, tested against the OWASP Benchmark suite, achieved a good balance of catching true issues while filtering out noise[datadoghq.com](https://www.datadoghq.com/blog/using-llms-to-filter-out-false-positives/#:~:text=There%20was%20a%20trade,and%20true%20positive%20detection%20rates). It’s a real-world example of an LLM working alongside a static analyzer as a second layer of judgment.
*   **Augmenting LLMs with Static Analysis for Code Quality (Arxiv 2025)** – _Autonomous code refinement agent._ Another line of work combines static analysis _feedback_ with LLM generation to not only find issues but also fix them. An arXiv study (Jun 2025) proposed a pipeline where an LLM is prompted to revise code to eliminate issues detected by a static tool[arxiv.org](https://arxiv.org/html/2506.10330v1#:~:text=This%20study%20examines%20the%20integration,LLMs%20in%20this%20domain%20could)[arxiv.org](https://arxiv.org/html/2506.10330v1#:~:text=generation%20,reduce%20time%20and%20resource%20expenditure). The workflow uses a static analyzer to flag potential problems, then a retrieval module to fetch relevant knowledge (documentation, known fixes), and then the LLM (GPT-3.5 or GPT-4) suggests code changes. A custom “code comparison” module checks the LLM’s patch for hallucinations or new errors before applying it[arxiv.org](https://arxiv.org/html/2506.10330v1#:~:text=generation%20,reduce%20time%20and%20resource%20expenditure). Iterating this loop led to significant reduction in code issues in their experiments[arxiv.org](https://arxiv.org/html/2506.10330v1#:~:text=identifies%20and%20corrects%20erroneous%20changes,reduce%20time%20and%20resource%20expenditure). This agentic approach essentially creates an automated bug-fixing loop: static analysis identifies a problem, LLM proposes a solution, and an automated test or checker validates it. It showcases how LLMs can be integrated into the continuous integration toolchain for code quality improvements.
*   **LLM-Powered Code Reviews** – _Beyond linting to design feedback._ Traditional linters check style rules, but LLMs can perform **semantic linting** – providing higher-level feedback on code logic, readability, and design. For instance, Bhattacharya (2023) notes that GPT-4 or Claude can act like an “AI pair programmer,” catching things human reviewers care about: “Is this function too complex? Does this code actually meet the requirements? Is there a better design here?”[codetirtho97.medium.com](https://codetirtho97.medium.com/llm-powered-code-reviews-beyond-static-analysis-tools-c68daad388db#:~:text=Similarly%2C%20static%20tools%20can%E2%80%99t%20tell,you)[codetirtho97.medium.com](https://codetirtho97.medium.com/llm-powered-code-reviews-beyond-static-analysis-tools-c68daad388db#:~:text=When%20reviewing%20a%20pull%20request%2C,an%20LLM%20might%20say). Unlike static tools that only see syntax, an LLM-based reviewer understands natural language and common patterns, allowing it to, say, suggest refactoring a regex that is brittle[codetirtho97.medium.com](https://codetirtho97.medium.com/llm-powered-code-reviews-beyond-static-analysis-tools-c68daad388db#:~:text=When%20reviewing%20a%20pull%20request%2C,an%20LLM%20might%20say) or point out duplicated code logic[codetirtho97.medium.com](https://codetirtho97.medium.com/llm-powered-code-reviews-beyond-static-analysis-tools-c68daad388db#:~:text=,Can%20it%20be%20abstracted%3F%E2%80%9D). GitHub has even introduced **Copilot for Pull Requests**, which uses an LLM to summarize code changes and answer questions like “Could this break backward compatibility?”[codetirtho97.medium.com](https://codetirtho97.medium.com/llm-powered-code-reviews-beyond-static-analysis-tools-c68daad388db#:~:text=GitHub%20recently%20introduced%20Copilot%20for,directly%20into%20code%20review%20workflows). The vision is a hybrid code review process: static analysis handles the low-level issues, LLMs comment on the nuanced design aspects, and human reviewers focus on domain-specific correctness[codetirtho97.medium.com](https://codetirtho97.medium.com/llm-powered-code-reviews-beyond-static-analysis-tools-c68daad388db#:~:text=,case%20validation). Early reports (e.g. McKinsey) suggest such AI assistance could cut code review and debugging time significantly (possibly ~30–40% improvement)[codetirtho97.medium.com](https://codetirtho97.medium.com/llm-powered-code-reviews-beyond-static-analysis-tools-c68daad388db#:~:text=This%20multi,in%20mature%20teams). Many of these are non-agentic (single prompt per diff or file), but they illustrate how LLMs are augmenting the code review workflow.

Semantic Linting and Intelligent Code Critique
----------------------------------------------

Semantic linting refers to lint-like rules enforced by AI understanding of context, rather than hard-coded patterns. A cutting-edge example is **Sublayer’s “Semantic Linting” tool**, announced in late 2025 as part of their Augmentations platform. It allows teams to define custom code review rules in natural language, which the Google Gemini LLM then applies across codebases[developers.googleblog.com](https://developers.googleblog.com/en/enhancing-ai-powered-developer-tools-with-gemini-api/#:~:text=Looking%20ahead%2C%20Sublayer%20is%20getting,into%20actionable%20insights%20for%20leadership). Because the LLM “understands” context, these rules can be high-level (e.g. _“any use of library X must be accompanied by a caching mechanism”_ or _“flag usage of recursion in performance-critical functions”_). The LLM evaluates if code follows the intent of those evolving best practices, effectively acting as a smart linter that knows the why, not just the what. This approach was shown to integrate with developer workflows by outputting structured suggestions that engineers can review each morning as pull requests[developers.googleblog.com](https://developers.googleblog.com/en/enhancing-ai-powered-developer-tools-with-gemini-api/#:~:text=After%20the%20success%20of%20this,to%20and%20review%20every%20morning)[developers.googleblog.com](https://developers.googleblog.com/en/enhancing-ai-powered-developer-tools-with-gemini-api/#:~:text=What%E2%80%99s%20next). Semantic linting bridges the gap between strict static checks and human judgment, as noted by Archer (2023): tools that mix deterministic parsing with generative suggestions can catch issues like inconsistent naming or inefficient patterns that a pure static tool might miss[tomarcher.io](https://tomarcher.io/posts/how-large-languag-models-read-code/#:~:text=Studies%20on%20code,instability%20when%20naming%20contradicts%20function)[tomarcher.io](https://tomarcher.io/posts/how-large-languag-models-read-code/#:~:text=suggestion%20may%20be%20statistically%20likely,but%20logically%20wrong). By combining an LLM’s pattern recognition with compiler precision, semantic linters can enforce code quality in a more holistic way.

LLM-Assisted README and Usage Example Generation
------------------------------------------------

Writing a good README or providing usage examples is another area being transformed by LLMs:

*   **README Generation Agents** – Developers have created agents that take an entire repository and produce a `README.md` file. For example, Pacheco (2025) built a GitHub README Agent using LangChain+LangGraph that can ingest a repo and output a detailed README in Markdown[medium.com](https://medium.com/@filipespacheco/i-created-an-ai-agent-to-build-readme-files-here-is-what-i-learn-3ae207771d37#:~:text=Well%2C%20after%20careful%20consideration%2C%20I,considered%20as%20an%20AI%20Agent)[medium.com](https://medium.com/@filipespacheco/i-created-an-ai-agent-to-build-readme-files-here-is-what-i-learn-3ae207771d37#:~:text=Markdown%20format%20based%20on%20the,repository%E2%80%99s%20contents). His agent uses GitHub API tools (to fetch repo structure, commit history, issues, etc.) and an LLM to ensure the README covers all key sections (overview, features, installation, usage, architecture, etc.)[medium.com](https://medium.com/@filipespacheco/i-created-an-ai-agent-to-build-readme-files-here-is-what-i-learn-3ae207771d37#:~:text=Available%20tools%3A%20,get_branches%3A%20Lists%20all%20branches)[medium.com](https://medium.com/@filipespacheco/i-created-an-ai-agent-to-build-readme-files-here-is-what-i-learn-3ae207771d37#:~:text=%E2%9C%85%20Recommended%20README%20Structure%20,Information%20on%20configuration%2C%20environment%20variables). Notably, it even inserts a **“Repository Structure”** section explaining each file/folder’s role[medium.com](https://medium.com/@filipespacheco/i-created-an-ai-agent-to-build-readme-files-here-is-what-i-learn-3ae207771d37#:~:text=%E2%9D%A4%EF%B8%8F%20Acknowledgements%20%E2%80%94%20Credits%20and,Retrieves%20the%20repository%27s%20commit%20history) and can optionally generate diagrams (via Mermaid) to illustrate component interactions. This is an agentic workflow – the LLM actively calls multiple tools to gather information, then synthesizes a coherent project description. The result is a comprehensive README generated in minutes, which the agent can then commit to the repo. Such agents demonstrate that even large-scale documentation (multi-thousand-word READMEs) can be drafted by AI with sufficient contextual data.
*   **Generate-README Eval (Patched.codes, 2024)** – _Benchmark for repo-to-README._ An engineering blog introduced a dataset and benchmark specifically for the task of generating a README from a full codebase[patched.codes](https://www.patched.codes/blog/evaluating-code-to-readme-generation-using-llms#:~:text=We%20introduce%20Generate%20README%20Eval%2C,SOTA%20model%20on%20this%20benchmark). They compiled 198 open-source Python projects, each with an existing README, and challenged various LLMs to reproduce those from the code. By keeping repository content under ~100k tokens, they could prompt models with _all_ the code (sans README) in a single call[patched.codes](https://www.patched.codes/blog/evaluating-code-to-readme-generation-using-llms#:~:text=We%20curate%20our%20dataset%20using,benchmark%20against%20all%20of%20them). They then evaluated the AI-generated README against the actual one using metrics like structural similarity (section headings), content overlap (mentioning key classes/functions), readability, and classic BLEU/ROUGE[patched.codes](https://www.patched.codes/blog/evaluating-code-to-readme-generation-using-llms#:~:text=To%20evaluate%20the%20LLM%20on,We%20describe%20them%20below)[patched.codes](https://www.patched.codes/blog/evaluating-code-to-readme-generation-using-llms#:~:text=Code%20Consistency). The best model (a fine-tuned Google Gemini variant) achieved a final score ~33 on their weighted scale, versus an “oracle” score of ~56 for the ground-truth README[patched.codes](https://www.patched.codes/blog/evaluating-code-to-readme-generation-using-llms#:~:text=We%20compared%208%20different%20models,0827)[patched.codes](https://www.patched.codes/blog/evaluating-code-to-readme-generation-using-llms#:~:text=Based%20on%20our%20evaluation%20we,results%20in%20the%20last%20section). This implies current models capture a fair amount of information but may miss deeper details. Interestingly, providing a few example repos (few-shot learning) didn’t dramatically improve performance, perhaps due to the already large context provided[patched.codes](https://www.patched.codes/blog/evaluating-code-to-readme-generation-using-llms#:~:text=To%20evaluate%20the%20performance%20by,quite%20large%20and%20models%20are). This benchmark spurred interest in training models specifically for repository summarization. It also highlights the challenges: a README isn’t just a dump of code comments – it must explain purpose and usage, which requires an understanding of the project’s intent.
*   **ReadMeAI (Docker Hackathon 2024)** – _Web app using PaLM for READMEs._ ReadMeAI is a tool that emerged from a Docker community hackathon[docker.com](https://www.docker.com/blog/readmeai-an-ai-powered-readme-generator-for-developers/#:~:text=This%20post%20was%20written%20in,Gitanshu%20Sankhla%20and%20Vijay%20Barma)[docker.com](https://www.docker.com/blog/readmeai-an-ai-powered-readme-generator-for-developers/#:~:text=from%20bug%20fixes%20and%20testing,powered%20README%20generator%20fits%20in). It lets a user upload their code files and a brief project description, and then uses Google’s PaLM LLM to generate a nicely formatted README.md. The UI allows real-time editing and preview of the generated markdown[docker.com](https://www.docker.com/blog/readmeai-an-ai-powered-readme-generator-for-developers/#:~:text=The%20ReadMeAI%20tool%20allows%20users,the%20changes%20are%20previewed%20instantly). The generated README typically includes sections like installation, usage examples, API endpoints, and contribution guidelines, populated by analyzing the code structure and the user’s description[docker.com](https://www.docker.com/blog/readmeai-an-ai-powered-readme-generator-for-developers/#:~:text=Use%20cases%20include%3A)[docker.com](https://www.docker.com/blog/readmeai-an-ai-powered-readme-generator-for-developers/#:~:text=%2A%20Open%20source%20project%20kick,consistent%20documentation%20across%20your%20projects). This tool is an example of a semi-automated workflow: the developer provides some guidance (a short description) and maybe tweaks after generation, but the heavy lifting of writing the first draft is done by the LLM. By focusing on one project at a time through a UI, it avoids needing a complex agent – it’s essentially a prompt crafted to turn “code + summary” into documentation. The use of a 540B-parameter model (PaLM) under the hood underscores that smaller code-specific models might not yet capture all nuances, but large models can output reasonably structured docs.
*   **Including Usage Examples** – LLMs can also generate usage snippets or examples for how to call functions, which is valuable for documentation. The MCP-based system mentioned earlier explicitly integrates _“usage example generation”_ in its API documentation workflow[ai.codersarts.com](https://www.ai.codersarts.com/post/mcp-powered-code-documentation-generator-intelligent-documentation-creation-with-rag-integration#:~:text=Automated%20API%20Documentation%20Generation). Similarly, ReadMeAI’s outputs for APIs include endpoint usage illustrations[docker.com](https://www.docker.com/blog/readmeai-an-ai-powered-readme-generator-for-developers/#:~:text=Use%20cases%20include%3A). In academic contexts, the **ReadMe.LLM framework (Wijaya et al., 2025)** flips this around: instead of LLM generating the usage example, they propose developers write _LLM-oriented documentation_ (including examples) to feed into the LLM[arxiv.org](https://arxiv.org/abs/2504.09798#:~:text=,is%20maintained%20alongside%20traditional%20software). By supplying an LLM with a special README designed for AI consumption, they achieved near 100% success in the LLM correctly using a niche library in code generation tasks[arxiv.org](https://arxiv.org/abs/2504.09798#:~:text=with%20only%20human,software%20libraries%2C%20highlighting%20that%20our)[arxiv.org](https://arxiv.org/abs/2504.09798#:~:text=we%20propose%20ReadMe%24.%24LLM%2C%20LLM,could%20generalize%20across%20programming%20domains). This suggests a two-way relationship – LLMs can produce examples for humans, and humans can craft examples for LLMs. Going forward, we may see LLMs integrated into developer tools where every function or API can have an AI-suggested example usage (like how to call it) alongside the code, effectively serving as always-updated documentation.

Conclusion
----------

Across documentation, analysis, and code understanding, specialized LLM-powered systems are rapidly emerging. Early results are promising: agents like DocAgent show that orchestrating multiple steps can significantly improve documentation quality[aclanthology.org](https://aclanthology.org/2025.acl-demo.44.pdf#:~:text=factually%20incor%02rect%20outputs,Our%20ablation%20study%20confirms%20the), while integrated tools like Bits AI in static analysis prove immediate industry value by reducing alert fatigue[datadoghq.com](https://www.datadoghq.com/blog/using-llms-to-filter-out-false-positives/#:~:text=Datadog%E2%80%99s%20new%20false%20positive%20filtering,the%20vulnerabilities%20that%20matter%20most)[datadoghq.com](https://www.datadoghq.com/blog/using-llms-to-filter-out-false-positives/#:~:text=An%20LLM%20introduces%20the%20ability,for%20exploitation%20are%20actually%20met). README generation and code summarization are also becoming feasible even for large repositories, especially with high-context models[patched.codes](https://www.patched.codes/blog/evaluating-code-to-readme-generation-using-llms#:~:text=We%20curate%20our%20dataset%20using,benchmark%20against%20all%20of%20them)[patched.codes](https://www.patched.codes/blog/evaluating-code-to-readme-generation-using-llms#:~:text=We%20compared%208%20different%20models,0827). A recurring theme is that **context is king** – whether via intelligent retrieval, multi-tool agents, or fine-tuned models on specialized data, providing the LLM with ample relevant context leads to the best outcomes and fewer hallucinations. Both agentic and non-agentic methods have their place: simple one-off prompts can quickly draft a docstring or suggest a fix, whereas agent-based workflows shine in complex tasks like documenting an entire codebase or performing iterative code refinement. The field is evolving fast, and we can expect even tighter integration of LLM “co-pilots” in software engineering pipelines, improving not only how we write code but also how we understand and maintain it.
